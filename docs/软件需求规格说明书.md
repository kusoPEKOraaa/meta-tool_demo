## 1. 用户需求

### 1.1 用户需求确定过程
本需求由 PM Agent 组织，在项目各阶段文档、现有 CLI 与 Web 功能基础上完成需求梳理，过程如下：

1. **项目现状盘点**：基于当前项目 README 与阶段文档，识别系统已有能力（CLI 分析、Web 可视化、报告与重构输出）。
2. **角色访谈模拟**：按课程场景抽象三类核心用户（学生开发者、教学人员、课程助教）并模拟其任务流程。
3. **痛点归纳**：聚焦“代码评审效率低、质量结果不直观、复盘材料分散”三类主要问题。
4. **需求评审**：由 PM Agent 协同开发 Agent、测试 Agent 对需求可实施性与可验证性进行审阅，输出可落地功能清单与优先级。

### 1.2 用户需求主要内容

#### 1.2.1 用户需求A：快速完成Python代码评审与修复

| 属性 | 内容 |
|---|---|
| 目标用户群体 | 学生开发者、初级Python工程师、需要快速检查作业代码的学习者。 |
| 典型使用场景 | 用户在提交作业或演示前，将 Python 代码粘贴到系统或通过 CLI 指定文件，系统自动识别语法/规范/风险问题并给出重构结果。 |
| 核心功能 | 代码输入、静态分析执行、问题分类、自动重构输出、报告生成。 |

#### 1.2.2 用户需求B：以可视化方式展示质量结果

| 属性 | 内容 |
|---|---|
| 目标用户群体 | 教学人员、课程助教、进行现场展示的项目成员。 |
| 典型使用场景 | 教师课堂演示时通过浏览器直接展示高/中/低问题数量、问题类别分布、AI 总结和重构前后差异。 |
| 核心功能 | Web 仪表盘、指标卡片、问题列表、Markdown 报告预览、重构代码预览。 |

#### 1.2.3 用户需求C：支持教学演示与过程复盘

| 属性 | 内容 |
|---|---|
| 目标用户群体 | 课程负责人、助教、项目评审人员。 |
| 典型使用场景 | 在阶段验收或课程考核中，导出分析报告并留存任务历史，用于对比不同版本代码质量变化。 |
| 核心功能 | 报告持久化、历史任务查询、可追溯执行信息（时间、输入摘要、结果统计）。 |

### 1.3 范围约束

**本项目需求范围包含：**
- Python 代码文本或文件输入。
- 针对语法、PEP8 风险、常见 bug 模式的静态检查。
- Markdown 格式评审报告生成。
- 机械式、安全优先的自动重构输出。
- CLI 与本地 Web 两种使用方式。

**本项目需求范围不包含：**
- 多语言（如 Java/Go/JS）深度语义分析。
- 云端多人协作、在线实时共同编辑。
- 企业级 CI/CD 平台集成（如 GitHub/GitLab 强绑定插件）。
- 生产级大规模并发部署与分布式架构。

## 2. 软件需求

### 2.1 软件需求整体描述
本项目是一个面向**教学演示与入门级质量治理**场景的 Python 代码评审软件（Meta-Tool），用于解决“人工代码检查耗时、质量问题定位慢、结果缺乏统一表达”问题，实现“自动化检查 + 结构化报告 + 可视化展示 + 安全重构”的目标。

### 2.2 软件需求概述

| 序号 | 功能模块名称 | 功能模块介绍 | 优先级 |
|---|---|---|---|
| 1 | 用户注册与登录 | 支持用户创建账号、登录系统与退出登录，保证用户可使用个性化功能和历史记录。 | 高 |
| 2 | 代码输入与样例加载 | 支持用户手动输入代码或加载内置样例，降低首次使用门槛。 | 高 |
| 3 | 代码分析引擎 | 执行语法、规范与风险规则检查，输出结构化问题清单。 | 高 |
| 4 | 可视化结果展示 | 显示总问题数、严重级别分布、问题类别、AI 总结等信息。 | 高 |
| 5 | 报告生成与导出 | 生成 Markdown 报告并支持保存，便于归档和复盘。 | 中 |
| 6 | 自动重构输出 | 对可安全改写项生成重构代码，辅助用户快速修复。 | 中 |
| 7 | 历史任务管理 | 保存历史分析任务并支持查询详情，支撑教学过程追踪。 | 中 |

## 3. 需求规格说明

### 3.1 功能需求FR-01：用户注册与登录

- **功能描述**：该功能用于提供用户身份识别与访问控制。未登录用户只能访问公开页面；登录后可执行代码分析、查看历史记录与导出报告。
- **前置条件**：系统已部署用户模块；数据库可读写；用户未被禁用。
- **触发条件**：用户点击“注册”或“登录”按钮并提交表单。
- **后置结果**：注册成功后创建账户；登录成功后建立会话并跳转到工作台。
- **依赖关系**：上游依赖数据库连接；下游影响历史记录归属与权限控制。
- **主流程**：
  1. 用户输入邮箱/用户名与密码；
  2. 系统校验必填字段与格式；
  3. 系统校验账号状态与密码正确性；
  4. 系统返回登录成功并创建会话令牌。
- **异常处理**：
  1. 参数非法：邮箱格式错误或密码长度不足，提示“参数无效”；
  2. 重复注册：账号已存在，提示“账号已注册”；
  3. 无权限：账号被禁用，提示“账号不可用”；
  4. 超时/接口失败：提示“服务暂不可用，请稍后重试”。
- **数据要求**：
  - 输入字段：`username`（必填，3-32字符，字母/数字/下划线）、`email`（必填，合法邮箱）、`password`（必填，8-64字符）。
  - 输出字段：`user_id`、`token`、`expire_at`、`message`。

### 3.2 功能需求FR-02：代码输入与样例加载

- **功能描述**：支持用户在 Web 文本框粘贴 Python 代码，或一键加载示例文件；CLI 支持文件路径输入，保证不同使用习惯用户都能快速触发分析。
- **前置条件**：用户已进入分析页面；系统可访问本地样例文件。
- **触发条件**：用户点击“加载样例”或“开始分析”；CLI 输入 `review_code <path>`。
- **后置结果**：系统完成代码读取并进入分析队列。
- **依赖关系**：上游依赖文件读取与编码检测；下游驱动分析引擎执行。
- **主流程**：
  1. 用户选择输入方式（粘贴/文件/样例）；
  2. 系统读取代码文本并做基础校验；
  3. 系统显示“可分析”状态并允许提交。
- **异常处理**：
  1. 无数据：输入为空，提示“请输入代码”；
  2. 参数非法：非 UTF-8 且无法解码，提示“文件编码不支持”；
  3. 文件不存在：提示“未找到目标文件”；
  4. 重复提交：按钮在分析中置灰并提示“任务处理中”。
- **数据要求**：
  - 输入字段：`source_code`（必填，最大 1 MB 文本）、`file_path`（CLI 可选，存在性校验）。
  - 输出字段：`normalized_source`、`input_mode`、`precheck_status`。

### 3.3 功能需求FR-03：代码静态分析执行

- **功能描述**：系统根据预设规则集对输入代码执行自动分析，识别语法错误、PEP8 风险及典型 bug 模式，输出结构化发现项。
- **前置条件**：代码预校验通过；分析规则已加载。
- **触发条件**：用户点击“开始分析”或 CLI 命令启动。
- **后置结果**：生成分析结果对象并持久化（可选）。
- **依赖关系**：上游依赖输入模块；下游依赖报告模块与可视化模块。
- **主流程**：
  1. 系统创建分析任务 ID；
  2. 调用语法检查器；
  3. 调用规范检查器；
  4. 调用风险模式检查器；
  5. 聚合结果并计算严重级别统计。
- **异常处理**：
  1. 超时：超过设定阈值未完成，提示“分析超时”；
  2. 接口失败：分析模块异常，返回错误码与日志追踪 ID；
  3. 无数据：规则未命中时返回“0问题”，并给出提示“未发现明显风险”。
- **数据要求**：
  - 输入字段：`task_id`、`source_code`、`provider`。
  - 输出字段：`issues[]`（`line`,`severity`,`category`,`message`,`recommendation`）、`summary`、`issue_count`。

### 3.4 功能需求FR-04：问题列表与严重级别展示

- **功能描述**：系统将分析结果以卡片和列表形式展示，帮助用户快速定位高风险问题并理解整体质量状态。
- **前置条件**：分析任务成功完成并返回结构化结果。
- **触发条件**：前端接收到分析完成事件。
- **后置结果**：页面更新总数、严重级别统计、类别分布及详细问题项。
- **依赖关系**：依赖 FR-03 输出；为 FR-05 报告生成提供可视数据来源。
- **主流程**：
  1. 系统渲染总问题数；
  2. 系统按高/中/低显示统计卡片；
  3. 系统按类别输出条形分布；
  4. 用户点击问题项查看建议与定位行号。
- **异常处理**：
  1. 无数据：显示“暂无问题数据”；
  2. 渲染失败：显示降级文本列表；
  3. 数据不一致：前端进行字段兜底并标记“部分信息缺失”。
- **数据要求**：
  - 输入字段：`issue_count`、`severity_breakdown`、`category_breakdown`、`issues[]`。
  - 输出字段：可视化组件状态对象与可复制文本摘要。

### 3.5 功能需求FR-05：Markdown报告生成与导出

- **功能描述**：系统根据分析结果自动生成标准化 Markdown 报告，内容包含摘要、问题详情与改进建议，并支持保存到本地目录。
- **前置条件**：分析任务已结束；报告模板可用。
- **触发条件**：用户点击“生成报告”或分析流程自动触发。
- **后置结果**：生成 `.md` 文件并返回保存路径。
- **依赖关系**：依赖 FR-03 结果对象；可被 FR-07 历史记录引用。
- **主流程**：
  1. 系统读取分析结果；
  2. 按模板渲染报告内容；
  3. 写入输出目录并返回文件名；
  4. 前端显示报告预览。
- **异常处理**：
  1. 模板缺失：回退到最小报告模板；
  2. 写入失败：提示“无写入权限或路径不可用”；
  3. 重名冲突：追加时间戳后缀自动重命名。
- **数据要求**：
  - 输入字段：`task_id`、`analysis_result`、`output_dir`。
  - 输出字段：`report_path`、`report_markdown`、`created_at`。

### 3.6 功能需求FR-06：自动重构输出

- **功能描述**：系统对具备确定性修复策略的问题执行机械式改写，输出重构后代码与变更说明，帮助用户快速完成基础修复。
- **前置条件**：分析结果可用；待改写规则在支持列表内。
- **触发条件**：用户点击“生成重构代码”或流程自动执行。
- **后置结果**：生成重构代码文件及变更摘要。
- **依赖关系**：依赖 FR-03 问题定位信息；下游可被用户下载或继续人工编辑。
- **主流程**：
  1. 系统筛选可自动修复的问题；
  2. 对源代码应用规则化改写；
  3. 生成新文件并记录变更条目；
  4. 返回重构前后代码预览。
- **异常处理**：
  1. 无可改写项：返回“未执行重构”；
  2. 改写冲突：回滚本次改写并提示“发现冲突”；
  3. 文件写入失败：提示“重构结果保存失败”。
- **数据要求**：
  - 输入字段：`source_code`、`issues[]`、`refactor_ruleset`。
  - 输出字段：`refactored_code`、`change_log[]`、`refactor_path`。

### 3.7 功能需求FR-07：历史任务记录查询

- **功能描述**：系统保存分析任务元数据和结果摘要，用户可按时间或任务 ID 查询历史任务，用于教学复盘和质量趋势对比。
- **前置条件**：用户已登录；历史存储启用。
- **触发条件**：用户进入“历史记录”页面并执行查询。
- **后置结果**：返回任务列表及指定任务详情。
- **依赖关系**：上游依赖 FR-03/FR-05 的结果持久化；下游支持导出与复盘。
- **主流程**：
  1. 用户输入筛选条件（时间范围/任务ID）；
  2. 系统查询并分页返回历史任务；
  3. 用户点击任务查看报告摘要与关键问题。
- **异常处理**：
  1. 无数据：提示“该条件下暂无任务”；
  2. 无权限：仅允许查看本人任务；
  3. 查询超时：提示“请求超时，请缩小时间范围后重试”。
- **数据要求**：
  - 输入字段：`user_id`、`task_id`（可选）、`start_time`、`end_time`、`page_no`、`page_size`。
  - 输出字段：`tasks[]`（`task_id`,`created_at`,`issue_count`,`high_count`,`status`）、`total`。

## 4. 非功能需求

1. **系统性能需求**
   - 对于不超过 500 行的 Python 代码，单次分析响应时间应 ≤ 3 秒（本地标准开发机环境）。
   - 对于 500–2000 行代码，分析响应时间应 ≤ 8 秒。
   - Web 页面首屏加载时间应 ≤ 2 秒（本地网络环境）。

2. **可靠性需求**
   - 核心分析流程可用性目标 ≥ 99%（教学演示时段）。
   - 分析失败时必须返回可理解错误信息与追踪 ID。
   - 报告写入失败时系统应保留内存结果并允许用户重试。

3. **易用性与可维护性需求**
   - 界面按钮、指标卡片与错误提示需使用统一文案规范，保证非技术用户可理解。
   - 模块化设计应支持分析规则独立扩展，不影响 CLI/Web 调用层。
   - 项目应提供基础单元测试，覆盖关键服务和分析模块。

4. **可移植性与兼容性需求**
   - CLI 运行环境兼容 Python 3.10 及以上。
   - Web 前端兼容 Chrome、Edge 的近两个主要版本。
   - 支持 Linux、macOS、Windows 开发环境启动。

5. **安全与权限需求**
   - 登录态接口应进行身份校验；历史记录只能由任务所属用户访问。
   - 用户输入的代码内容仅用于本次分析，不用于未经授权的外部传输。
   - 关键操作（登录失败、分析失败、导出失败）应记录审计日志。
